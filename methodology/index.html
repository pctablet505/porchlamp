How Porchlamp measures a project

Porchlamp ranks open-source projects by what happens to a stranger's pull request. This page lists every rule, weight and parameter behind the ranking, generated from the same constants the ranking code uses.

This page describes snapshot 2026-10-17. The black-hole report and the rankings use the same rules.

Gates

Checks a repository must pass to be ranked. A repository that fails one carries the gate's reason instead of a rank.

D-GATE-1: Software project

repository tree contains a recognised build/package manifest at depth <= 2, or the repository is a curated anchor

D-GATE-2: Not archived, not a mirror, not a fork

archived == false, mirror_url is null, fork == false (a fork is allowed only if its parent is absent from the universe)

D-GATE-3: Licensed

SPDX id present and OSI-approved; an undetermined SPDX id falls back to a LICENSE* file search before the gate fails

D-GATE-4: Vitality

>= 1 commit by a non-bot User on the default branch in the trailing window

D-GATE-5: Not a black hole

over external PRs by non-bot authors (D-IN-1) opened in the trailing PR window and at least the minimum age, the 95% one-sided Wilson lower confidence bound (z = 1.6448536269514722) on the zero-response share must not exceed the ceiling (a minimum population of 10 is required, else the gate is UNDECIDED rather than failed, and a repository whose PR records lack the fields the exclusions below read is UNDECIDED, neither passed nor failed: the missing fields move the share both ways); the raw share is the gr14_ghost_rate parameter, computed for such a repository without the rules those fields feed (the draft and self-close exclusions, and a maintainer close counted as a response). A reply or review counts when it is substantive (D-IN-2: any review, or a comment of 40+ characters, by a non-author, non-bot member, owner or collaborator, or by an account that merged a PR in the window, since org membership can be private); a merge or maintainer close within the deadline counts on its own. Five false-positive exclusions apply (RFC-0008, RFC-0010): draft PRs are excluded until marked ready for review (clock starts at ready_at); author self-closed PRs with no earlier maintainer response are excluded only when the author closed them within the 14-day response deadline from clock start, and a later self-close with no response counts as unanswered; accounts under 90 days old (MIN_ACCOUNT_AGE_DAYS) are excluded; maintainer closes within 14 days count as responses; and the 14-day observation age is judged from clock start against min(now, observed_at)

D-GATE-6: PR workflow

>= 1 external PR (bots included: the gate asks whether the repository works through GitHub pull requests at all) decided (merged or closed) in the trailing decision window, read from the recorded PR window, the 365-day author history and the 30 newest PRs, or off-platform markers present (routed, not failed); neither means unrated: no_external_workflow, but only when those records hold the repository's whole PR history (the 30 newest were fewer than 30, and no window or history read beside them is truncated): otherwise the gate is UNDECIDED, because a PR opened before the records may have been decided inside the window. Each record shows decisions up to its own fetch. A repository also routes off-platform, whatever its decided PRs, when it hands review off: among its outside PRs (external, non-bot authors in the recorded PR window) at least 5, and at least 50% of them, carry a notice, a comment by an account other than the PR's author that contains "has been imported to gerrit for code review", "welcome to gitgitgadget" or "import it to our internal repository for further review" (any letter case) or is written by an account whose login starts with "gitgitgadget". D-GATE-5 is then undecided for it, never failed

D-EVID-1: Evidence sufficiency

composite coverage must reach the rated minimum, else listed unranked

Missing data

What a missing input means, and how much coverage a repository needs before it is rated.

  • Unrated below: 60%
  • Tier ceiling B below: 80%
  • Tier ceiling A below: 95%

Why a measurement can be missing:

  • third_party_gap: A third party (a registry, OpenSSF, deps.dev) never provided the fact; no maintainer action can close this gap.
  • collector_failure: The collector attempted to measure this input and failed (a fetch error, a stale window anchor); a retry can still measure it.
  • insufficient_n: The input was measured but its sample size fell below the parameter's minimum n; the measurement is recorded but scored as unmeasured.
  • not_applicable: The parameter is undefined for this repository's class by a closed, design-level rule (D-MISS-5); excluded from both the numerator and the denominator of coverage.
  • no_population: The parameter is ECDF-normalised and no rated, measured repository exists in its ecosystem or globally at this snapshot to build a population from.

Tie-break order

When two composites are equal, these fields separate them, in this order.

  1. composite, descending: rounded to 2 decimal place(s) before comparison
  2. coverage, descending
  3. responsiveness_pillar_score, descending
  4. friction, ascending
  5. leverage, descending
  6. ttfhr_p75_hours, ascending: p75, not the median: consistency, not just the typical case
  7. last_non_bot_commit_at, descending
  8. owner_name_lowercase, ascending: deterministic last resort; never stars, forks or downloads

Limits

  • Not a verdict on the people who maintain these projects. Review time is scarce, and popular projects receive far more pull requests than anyone can read.
  • GitHub only. Projects that review on Gerrit or a mailing list are left undecided, not failed.
  • One six-month window. The numbers will change at the next snapshot.
