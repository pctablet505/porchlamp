Methodology and snapshot

Benchmark 2.0.0-rc1 · schema 2 · constants hash be7023c09aa5…

Why Porchlamp

The Idea

A porch lamp left on tells a visitor they are expected. Porchlamp ranks open-source projects the same way: by what happens to a stranger's pull request, not by how many stars the project has.

The Finding

Stars do not review pull requests. In our measurements more than 1 in 5 active projects leave most pull requests from outside contributors without a human reply, review or merge for 14 days, and the more stars a project has, the more likely it is to be one of them. We call these projects black holes; they are listed under Not ranked, never ranked.

The Evidence

Every number comes from public GitHub activity: how fast a person answered outside contributors, how many of their pull requests reached a decision, whether first-time contributors came back, and how much other software depends on the project.

  • D-GATE-5

    Not a black hole

    over external PRs by non-bot authors (D-IN-1) opened in the trailing PR window and at least the minimum age, the 95% one-sided Wilson lower confidence bound (z = 1.6448536269514722) on the zero-response share must not exceed the ceiling (a minimum population of 10 is required, else the gate is UNDECIDED rather than failed, and a repository whose PR records lack the fields the exclusions below read is UNDECIDED, neither passed nor failed: the missing fields move the share both ways); the raw share is the gr14_ghost_rate parameter, computed for such a repository without the rules those fields feed (the draft and self-close exclusions, and a maintainer close counted as a response). The gate judges only a PR record that covers the whole window. The collector records every PR opened in the window; when there are more than 2,000, it records replies and reviews on an even random sample of 1,000 of them, drawn by PR number with a fixed seed, and the gate uses the sample's share and size (RFC-0013). A record that stops short of the window's start is UNDECIDED, never judged on the newest weeks as if they were the window; the time the record starts (the cut-off) is recorded with the gate's evidence (RFC-0011). A reply or review counts when it is substantive (D-IN-2: any review, or a comment whose text, without markup, is at least 40 characters long, each Chinese, Japanese or Korean letter counting 3 times, since those scripts say in one letter about what Latin text says in three) by the repository's own people: an account that is not the PR's author, not a bot (D-IN-1), and is a member, owner or collaborator, or merged a PR in the recorded window, or closed a PR someone else opened there. Merging or closing another author's PR takes repository access, whatever association GitHub shows: org membership can be private, and committers who land changes outside GitHub show as contributors. A merge or maintainer close within the deadline counts on its own. Five false-positive exclusions apply (RFC-0008, RFC-0010): draft PRs are excluded until marked ready for review (clock starts at ready_at); author self-closed PRs with no earlier maintainer response are excluded only when the author closed them within the 14-day response deadline from clock start, and a later self-close with no response counts as unanswered; accounts under 90 days old (MIN_ACCOUNT_AGE_DAYS) are excluded; maintainer closes within 14 days count as responses; and the 14-day observation age is judged from clock start against min(now, observed_at)

    Reasons
    black_hole
    Cutoffs
    min_n10min_age_days14response_deadline_days14max_zero_response_share0.5
  • D-GATE-6

    PR workflow

    >= 1 external PR (bots included: the gate asks whether the repository works through GitHub pull requests at all) decided (merged or closed) in the trailing decision window, read from the recorded PR window, the 365-day author history and the 30 newest PRs, or off-platform markers present (routed, not failed); neither means unrated: no_external_workflow, but only when those records hold the repository's whole PR history (the 30 newest were fewer than 30, and no window or history read beside them is truncated): otherwise the gate is UNDECIDED, because a PR opened before the records may have been decided inside the window. Each record shows decisions up to its own fetch. A repository also routes off-platform, whatever its decided PRs, when it hands review off: among its outside PRs (external, non-bot authors in the recorded PR window) at least 5, and at least 50% of them, carry a notice, a comment by an account other than the PR's author that contains "has been imported to gerrit for code review", "welcome to gitgitgadget", "import it to our internal repository for further review", "this pull request has been imported" or "has imported this pull request" (any letter case) or is written by an account whose login starts with "gitgitgadget". D-GATE-5 is then undecided for it, never failed

8

What a missing input means

third_party_gap
A third party (a registry, OpenSSF, deps.dev) never provided the fact; no maintainer action can close this gap.
collector_failure
The collector attempted to measure this input and failed (a fetch error, a stale window anchor); a retry can still measure it.
insufficient_n
The input was measured but its sample size fell below the parameter's minimum n; the measurement is recorded but scored as unmeasured.
not_applicable
The parameter is undefined for this repository's class by a closed, design-level rule (D-MISS-5); excluded from both the numerator and the denominator of coverage.
no_population
The parameter is ECDF-normalised and no rated, measured repository exists in its ecosystem or globally at this snapshot to build a population from.

Limits

  • Not a verdict on the people who maintain these projects. Review time is scarce, and popular projects receive far more pull requests than anyone can read.
  • GitHub only. Projects that review on Gerrit or a mailing list are left undecided, not failed.
  • One six-month window. The numbers will change at the next snapshot.
